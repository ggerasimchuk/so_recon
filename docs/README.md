# SO-RECON — комплект архитектурной документации

**Дата:** 13 сентября 2026 г.  
**Назначение:** исходный комплект для подготовки поэтапных планов и реализации проекта ВКР/статьи «Локализация остаточных запасов нефти с применением методов машинного обучения».

## Файлы

1. **`SPEC.md`** — нормативная архитектурная спецификация. Определяет target, физическую постановку, роль ML, posterior inference, продукты, validation gates и условия отказа от ложной точности.
2. **`DATA_AUDIT.md`** — независимый аудит пяти фактических CSV из `/vkr`: схемы, ловушки чтения, объёмы, временное/пространственное покрытие и вывод о пригодности данных.
3. **`RESEARCH.md`** — научный синтез литературы, сравнение альтернатив и обоснование выбранной архитектуры.

При конфликте документов приоритет имеет `SPEC.md`. Фактическая ошибка в данных требует обновления версии спецификации, а не скрытого изменения реализации.

## Ключевое решение

Текущая нефтенасыщенность не используется как обычный supervised-target: доступные значения ГИС относятся к моменту вскрытия, смещены эпохой интерпретации и почти не содержат надёжной прямой разметки изменения `So` от разработки.

Проект решает задачу как байесовскую обратную задачу:

```text
conditional geological ensemble
        +
completion/event history
        +
JutulDarcy oil–water simulation
        +
graph-temporal FMPE posterior proposal
        +
exact likelihood / defensive tempered SMC correction
        =
weighted posterior ensemble of current So fields
```

ML является центральным обучаемым обратным оператором, но финальные состояния всегда пересчитываются физическим симулятором.

## Нормативные границы

- основной forward backend: **JutulDarcy**;
- OPM допустим только как независимая synthetic-проверка;
- основной результат на реальных данных: реконструкция на **31.12.2020**;
- 31.12.2024 — дополнительный сценарный результат из-за неполной поздней истории подключений;
- МЭР не разносится по пластам фиксированными долями до симуляции;
- `So_log` — noisy/bias-aware observation, не безошибочный target;
- все финальные posterior particles проходят exact forward run;
- карта публикуется только на масштабе, прошедшем resolution/calibration gates;
- при недостаточной наблюдаемости система обязана abstain.

## Статус старых документов

Этот комплект **заменяет** предыдущие `so_project_specification.md` и `STAGES.md`, в которых различались основной симулятор и схема инверсии. Старые документы можно использовать только как исторический материал; они не задают требования новой реализации.

## Как передавать агенту

Агент должен сначала прочитать файлы в порядке:

1. `README.md`;
2. `DATA_AUDIT.md`;
3. `RESEARCH.md`;
4. `SPEC.md`.

После этого следует отдельно создавать планы реализации по этапам. План не вправе менять target, информационный режим, same-physics baselines, закрытые тесты и критерии приёмки из `SPEC.md`.
