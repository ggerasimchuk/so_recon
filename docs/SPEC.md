# 1. Архитектура в одном абзаце

SO-RECON восстанавливает текущее поле нефтенасыщенности как скрытое состояние вероятностной геолого-гидродинамической модели. Геология, подключения и история суммарного отбора жидкости/закачки задают прямую задачу **JutulDarcy**. Первые малые эксперименты используют нефть–вода; физический класс полевого пилота фиксируется по обязательной проверке gas/PVT/capillarity, а не выбирается из-за размера RAM. Наблюдаемый фазовый состав и датированные интерпретации ГИС ограничивают неизвестные параметры. Центральный ML-модуль — **пространственно-временной графовый кодировщик + условный Neural Spline Flow (NSF)** — обучается на синтетических историях и предлагает распределение физических объяснений данных. **Defensive tempered SMC** корректирует предложение по prior и полной физической likelihood. Каждый конечный вариант поля рассчитывается симулятором. Выход — взвешенный ансамбль So, объёмов оставшейся нефти, неопределённости и физически проверяемых возможностей доразработки.

## 1.1. Один путь от входа к результату

```text
Пять CSV + подтверждённые внешние сведения
    → канонические данные, QC, единицы, временная доступность
    → условный геологический prior + история подключений/их неопределённость
    → JutulDarcy: физические разработки с известными параметрами и So
    → synthetic corpus: геология/режимы/наблюдения ↔ физические параметры
    → graph-temporal encoder + conditional NSF: предложение q(theta | history)
    → SMC: prior + proposal density + полная likelihood JutulDarcy
    → posterior particles {theta, So(t), p(t), weight}
    → карты состояния, оставшейся нефти, поддержки и неопределённости
    → парные контрфактические сценарии новой скважины/поддерживаемого ГТМ
```

Начальная среда — MacBook Pro M4 Pro с 24 ГБ объединённой памяти. Полный путь сначала выполняется на малом двухслойном синтетическом мире и только затем переносится на полевой сектор. Уменьшается размер эксперимента, но сохраняются неизвестные параметры, нормированная likelihood, ML-плотность, физическая коррекция и проверка истинной So.

Это не несколько моделей, голосующих за разные карты. ML является обратным распознавателем внутри одной вероятностной задачи; физический state единственный. Нейросетевой forward surrogate, PINN, GAN/diffusion-геология и собственный solver **не входят** в обязательную архитектуру.

## 1.2. Что именно улучшает ML

При одинаковой полной модели идеальный posterior одинаков с ML и без него. Поэтому главный проверяемый вклад — **лучшее восстановление скрытой So при ограниченном вычислительном бюджете**: полезные предложения, поиск разных мод, меньшая ошибка и/или лучшая калибровка. Это не создание новых измерений и не априорное превосходство над гидродинамическим моделированием.

Доказательство требует сравнения со SMC из prior, сильным ансамблевым history matching и многозапусковой adjoint-инверсией. Сравнение только с интерполяцией или слабой табличной регрессией недостаточно. Обязательно считаются стоимость синтетики, обучения и коррекции, а не только скорость готовой нейросети.

# 3. Таргеты и физические определения

## 3.1. Разделение насыщенностей

`So(x,t)` — текущая доля порового объёма, занятая нефтяной фазой. `Soi(x)` — доразработочная нефтенасыщенность. `S0(x)` — насыщенность на фактическом старте расчёта; если разработка началась раньше истории, S0 не равна автоматически Soi. `Sorw(x)` — параметр остаточной нефтенасыщенности после вытеснения водой в модели ОФП. `So_log` — интерпретированное наблюдение ГИС на собственной дате с ошибкой и конечным пространственным support.

В black-oil классе:

`So + Sw + Sg = 1; 0 <= S_alpha <= 1`.

Тождество `So=1−Sw` разрешено лишь в проверенном режиме без свободного газа. В части электрических интерпретаций измеряемая величина может быть `So+Sg`; это учитывается оператором наблюдения, а не решается названием столбца.

Нельзя заставлять `So >= Sorw` во всех ячейках: природная водяная зона может содержать меньше нефти. Нельзя требовать монотонного снижения So в каждой ячейке: пространственное перераспределение фаз может давать локальный рост.

## 3.2. Обводнённость — поток, а не насыщенность

Для совместимых стандартных объёмов за месяц:

`fw_obs = Vw_sc / (Vo_sc + Vw_sc)`.

Симулятор предсказывает именно интегральные объёмы, затем их отношение. В идеализированном локальном oil–water течении без дополнительных различий фазовых градиентов пластовый fractional flow равен `lambda_w/(lambda_w+lambda_o)`, где `lambda_alpha=kr_alpha/mu_alpha`. При переводе к стандартным объёмам в таком частном случае появляется отношение `lambda_w/Bw` к сумме `lambda_w/Bw + lambda_o/Bo`. Для общей многопластовой скважины используется штатный скважинный оператор, а не эта формула напрямую.

Следовательно, `So=1−fw`, «инверсия watercut по единственной универсальной кривой» и её пространственная интерполяция запрещены как основной количественный метод.

## 3.3. Объёмы нефти

Для ячейки с bulk volume V, NTG и пористостью phi:

`PV = V * NTG * phi`.

Если V уже эффективный коллекторский объём, NTG повторно не умножается. Для black-oil без испарённой нефти:

`N_rem_sc(t) = sum_c PV_c * So_c(t) / Bo_c(t)`.

`N_above_Sor_sc(t) = sum_c PV_c * max(So_c(t) − Sorw_c, 0) / Bo_c(t)`.

Вторая величина — **объём нефти выше принятого порога Sorw**, не гарантированные извлекаемые запасы. В трёхфазной области дополнительно выводятся kr_o и чувствительность к ОФП: один порог не описывает всю подвижность. При расширении физики на испарённую нефть формула инвентаря компонента должна быть изменена согласованно; основная black-oil конфигурация принимает Rv=0 и явно хранит это допущение.

Масса получается умножением на подтверждённую стандартную плотность. До подтверждения единиц/PVT допускаются карты насыщенности и сценарные объёмы с явным статусом, но не аттестованные тонны запасов.

## 3.4. Выходы

Обязательны: posterior поля So и его неопределённости по слоям; распределение оставшегося нефтяного инвентаря; объём выше Sorw; карты информативности и зависимости от допущений; ансамблевые сценарии дополнительного отбора. Отдельная обучаемая «модель запасов» поверх So не нужна: объёмы вычисляются из каждого согласованного физического состояния.

# 4. Пространство, даты и информационные режимы

## 4.1. Два объекта: ранний синтетический и полевой

**Первый сквозной объект — малый неоднородный двухслойный synthetic world**, а не сектор из десятков тысяч ячеек. Профиль `P1_LOOP` по умолчанию имеет 16×16×2 = 512 ячеек, 4–8 скважин и 36–60 отчётных месяцев; допустимые диапазоны и бюджет заданы в COMPUTE_PROFILES.md. В нём уже неизвестны проводимости, исходное насыщение, отдельные параметры ОФП/подключений; есть скрытая от модели So. Подробности обязательного опыта — §22.

**Первый полевой объект — гидродинамически связанный сектор Д1 с buffer.** Для `P2_PILOT` ориентир 1 000–3 000 активных ячеек, для основного `P3_RESEARCH` — 2 000–10 000. Это начальные масштабы, не гарантии производительности и не предел допустимой сетки. 10–80 тыс. ячеек не является требованием проекта. Сгущение выполняется только по чувствительности результата и измеренному ресурсу.

Полевая модель сохраняет стратиграфические единицы `Д1А, Д1Б1, Д1Б2, Д1Б3, Д1В, Д1Г1, Д1Г2, Д1Г3, Д1Д` там, где они присутствуют. Составные обозначения задают множества/неопределённое соответствие, а не дополнительный PV. Двухслойный учебный мир не оправдывает слияние девяти реальных слоёв. Горизонтальное укрупнение и агрегация публикуемых результатов допустимы; физически значимые вертикальные экраны не исчезают.

Исходная сетка пилота — слоистая призматика/Cartesian-topology с геологическими кровлями и подошвами, переменным горизонтальным шагом по необходимости. PEBI/unstructured не обязательны сами по себе; переход требуется при существенной геометрической/анизотропной ошибке. Применимость TPFA проверяется; при её нарушении используется поддержанная согласованная дискретизация, не молчаливое обнуление анизотропии.

Размер core выбирается по связности и покрытию, а не по фиксированному числу скважин. Стартовые ориентиры числа core-скважин приведены в профилях; влияющие внешние скважины входят в buffer дополнительно. Число ячеек **включает buffer**. Если он не помещается, выбирается меньший core, иной пилот или внешняя машина; нельзя обрезать внешнюю закачку и сохранить прежний научный статус.

Публикуемый support определяется независимо от сетки. Для полевого development проверяются фиксированные зоны примерно 500 м, 1 км, 1.5 км либо геологически обоснованные блоки; более мелкий support требует отдельного доказательства. Выбор правила фиксируется до confirmatory test. Независимые секторные posterior нельзя просто сшить и представить как совместную модель всего месторождения.

### 4.1.1. Короткая история не означает обнулённую разработку

Для искусственного `P1_LOOP` t0 — настоящий старт выбранного учебного мира. Для реального пилота история не обрезается до последних 36–60 месяцев с повторной virgin-инициализацией. Используются доступная предыстория, её неопределённая реконструкция или физически допустимый prior S0. Restart другой геологической частицы нельзя использовать как начальное состояние новой частицы. Укороченные реальные окна — только отладочный режим с маркировкой, если предыстория не восстановлена.

### 4.2.1. Выбор t_ref и запрет выбора по результату модели

E05 составляет `CompletenessReport` по всем кандидатам: core/buffer и связанные пласты; доля потоковых месяцев с известными units/ролью/подключением; объём потоков в неопределённых окнах; поддержка предыстории; dated/undated ГИС; доступность будущего окна 12/24 месяца; источники pressure/PVT. Доля неопределённости считается и по числу записей, и по объёму, чтобы малочисленные крупные потоки не потерялись.

До history matching E05 фиксирует правила допустимости и ранжирование дат только по этим признакам. По умолчанию выбирается самый поздний допустимый cutoff с требуемым будущим окном; 2020 сохраняется кандидатом без привилегии «полный». Неразрешённые identity/units, неучтённый значимый связанный пласт или отсутствующая модель предыстории исключают количественный статус независимо от процента заполнения. Остальные допустимые пороги и сценарные окна записываются в паспорт до сравнения методов. E06–E07 могут отклонить выбранный опыт по физической пригодности; новый выбор получает новый experiment_id и не использует скрытые будущие отклики. E08 замораживает решение перед confirmatory test. Если пригодной даты нет, фиксируется ограничение данных, а не выбирается дата с наименьшим ML loss.

## 4.3. Четыре режима, которые нельзя смешивать

| Режим | Доступные сведения | Допустимое утверждение |
|---|---|---|
| Retrospective smoothing | Все разрешённые сведения, включая более позднюю геологию; каждое наблюдение используется на своей физической дате | Наилучшая ретроспективная реконструкция при нынешнем знании |
| Strict as-of | Только сведения с availability_date <= cutoff | Что можно было оценить на указанную дату |
| Conditional response forecast | Исторический cutoff; будущие фактические суммарные управления известны и объявлены условиями | Прогноз фазового отклика при заданной будущей эксплуатации |
| Policy/counterfactual forecast | Только доступное прошлое и сформулированная будущая политика BHP/мощностей | Физически допустимый сценарий решения |

Успех conditional forecast нельзя называть безусловным прогнозом добычи. Поздний ГИС допускается в smoothing, но является утечкой для blind as-of теста, если объявлен недоступным до бурения.

# 5. Единая вероятностная модель и наблюдаемость

Обозначим `G` разрешённые статические сведения, `U_obs` историю суммарных управлений, `Y` фазовые и датированные геофизические наблюдения. Параметры `theta=(s,v,z_perp)` включают дискретные структурные/операционные гипотезы s, информативные непрерывные координаты v и сохранённый геологический остаток z_perp. В theta входят также параметры ошибок, PVT/ОФП, начального состояния и внешнего обмена; их конкретная принадлежность подпространствам фиксируется схемой.

Прямой оператор:

`X_0:T = F_Jutul(theta, G, U_true(theta,U_obs))`.

Условный posterior:

`pi(theta | Y,G,U_obs) ∝ p0(theta | G,U_obs) * L(Y | F_Jutul(theta),theta)`.

Зависимость p0 от U_obs обозначает только объявленную условную модель неопределённости входных управлений и подключения, не скрытое повторное обучение prior по тем же фазовым откликам. Статические сведения, использованные для conditioning prior, не умножаются второй раз как независимая likelihood. Насыщенность позднего ГИС не входит в «начальную геологию» без временного оператора.

## 5.1. Что ограничивается данными, а что может остаться неопределённым

Динамика помогает ограничить пути потока, распределение вытеснения, эффективную связность и доли фазового притока. Но абсолютная проницаемость, давление, PVT, граничная поддержка и ряд сочетаний skin/ОФП могут быть слабо различимы. В частном несжимаемом fixed-rate случае без гравитации/капиллярности масштабирование K и компенсирующее изменение градиента p оставляют скорости неизменными. Это демонстрирует, почему отсутствие давления создаёт неидентифицируемые направления; в полной модели симметрия может нарушаться, но слабая чувствительность остаётся предметом теста.

Для каждой поддерживаемой зоны проверяются prior→posterior изменение, чувствительность к семействам, конкурирующие модели с одинаковым history match и разные So. Хорошая подгонка fw — необходимая, но недостаточная проверка состояния.

## 5.2. Давление

Давление является скрытым состоянием решателя. Начальное давление из внешнего источника ограничивает инициализацию с указанием глубины приведения и даты; оно не создаёт исторический ряд. Предсказанное давление запрещено выдавать за измеренную ML-фичу или использовать как независимую pseudo-label.

Без давления допускается реконструкция, но не обещается идентификация каждого параметра. Система обязана показать, насколько неопределённость p/PVT влияет именно на oil-specific So и возможности отбора.

# 6. Каноническая модель данных

## 6.1. Общие правила

Raw неизменяемы; сохраняются SHA-256, кодировка, разделитель, исходные номер строки/колонки. Все численные данные имеют unit, conditions и quality. Нормализованный well_id — строка: суффиксы и кириллица/латиница сохраняются; отдельный well_family_id не даёт права объединять стволы.

Нули, пропуски, простои и недействительные величины различаются. Невероятные So/phi не обрезаются молча. Известные особенности ширины CSV обрабатываются адресными правилами; строки не сдвигаются ради соответствия заголовку. Каждое исправление трассируется к исходнику.

## 6.3. Координаты и геометрия

CRS не угадывается по большим X/Y. До подтверждения допустим локальный метрический frame с явной неизвестной геодезической привязкой. Плановые координаты по пласту не считаются полноценной инклинометрией. Вертикальная скважина — гипотеза для стволов без траектории; наклонные/боковые стволы требуют неопределённой геометрии или исключения из количественного core.

MD, TVD, абсолютная отметка и альтитуда не смешиваются. Единая конвенция z/гравитации выбирается в адаптере и проверяется на гидростатике. Отрицательная толщина/пересечение геологических поверхностей обрабатываются до симуляции, а не исправляются инверсией.

## 6.4. События и подключения

История строится геометрическими операциями над интервалами. Первичная перфорация/дострел добавляют открытый интервал; изоляция/отключение вычитают соответствующий участок. Перестрел не создаёт новый поровый объём и не удваивает площадь; он может изменять множитель WI в отдельной группе воздействия. Повтор одного физического события в нескольких строках не дублирует его эффект.

`Открыт` используется как возможный поздний snapshot, не как истинный статус за все годы. При положительной МЭР до первой перфорации вводится неизвестное начальное подключение, совместимое с известными интервалами/объектами. Для позднего периода строятся ограниченные сценарии неизвестных событий, опирающиеся на смены layer_set, известные интервалы и частоту сопоставимых работ; произвольное ежемесячное изменение WI запрещено.

Дискретные гипотезы — конечные альтернативы по конкретным неопределённым временным окнам. Не создаётся отдельный сценарий для каждой мыслимой геологической ошибки. Слишком большое число неограниченных событий означает неподходящий пилот или сценарный статус, а не разрешение зафиксировать все подключения без uncertainty.

Отключение от поверхности и закрытие соединений различаются: в JutulDarcy `DisabledControl` допускает внутренний обмен, если подключения не закрыты маской [R02](SOURCES.md#r02). Это проверяется отдельными тестами crossflow.

## 6.5. Многопластовость

Список объектов МЭР задаёт ограничения на возможные подключения. Фактический фазовый вклад слоя вычисляется скважинной моделью по потенциалу, WI и подвижности. Предварительное фиксированное разнесение по толщине/kh не является наблюдением и не используется для обучения.

Если одна скважина соединяет core с неучтённым пластом, этот пласт должен быть добавлен с неопределённостью или скважина/сектор не проходит gate. Запрещено отдавать весь её дебит Д1 и затем подгонять So под ошибочно приписанный отбор.

## 6.6. Проверяемые схемы и инварианты таблиц

Таблицы §6.2 — логические контракты. E04 фиксирует физические имена/типы и nullability в versioned schema; E05 дополняет временные сущности. При переименовании сущности из 3.0 сохраняется явное отображение: `well_registry` → wells/coordinates, `geology_intervals` → geological_intervals/log_observations, `well_month` → monthly_volumes, `completion_state_month` → completion_segments, `observation_registry` → observations. Уже существующие потребители не ломаются молча; промежуточная месячная completion view допустима поверх сегментов.

Обязательны следующие ключи и проверки:

- wells: уникальный строковый well_id, исходные aliases и provenance; family_id не заменяет identity ствола;
- интервалы: устойчивый interval_id и ссылка на well_id, top/base с единицами и MD/TVD-конвенцией; top < base, принадлежность слою и uncertainty;
- monthly_volumes: well_id, границы месяца и исходный row_id; дубликаты сначала диагностируются, затем агрегируются по объявленному правилу; phase/standard-volume семантика сохраняется;
- события: event_id, event_time/интервал неопределённости, геометрия воздействия, исходные строки; повтор события идемпотентен;
- completion_segments/controls: непересекающиеся интервалы в пределах выбранной гипотезы и ствола; дискретные сценарии не смешиваются в одно расписание;
- observations/log_observations: observation_id, physical support, measurement/date interval, availability, units, quality, missing reason, operator и исходные строки; вход prior и likelihood не учитывает одно наблюдение дважды;

Баланс ETL проверяется по фазовым суммам и числу исходных строк до/после преобразований с раздельным ledger карантина. Исходные значения, интерпретация, единицы и причина пропуска доступны для трассировки. Параметры будущей научной модели не заполняются данными из закрытой части.

# 7. Геологический prior и параметризация

## 7.1. Структурные семейства

s включает небольшое число геологически оправданных вариантов связности/границ, семантики насыщенности и дискретных подключений. При отсутствии подтверждённых разломов не генерируется произвольная сеть разломов. Не строится бесконтрольное декартово произведение сотен допущений: сначала sensitivity screen на training cases, затем фиксированный набор поддержанных альтернатив.

Плотность p0(s) и условные законы параметров известны. Сценарии с равной вероятностью допустимы только как явно заданный prior, который затем обновляется, а не как автоматически равные posterior weights.

## 7.2. Условная геология

Модель строит ансамбли кровли/подошвы, коллекторского присутствия, phi, log(k), анизотропии и вертикальной связности. По умолчанию — условные геостатистические поля с трендами и известной латентной плотностью; распределения и корреляционные масштабы проверяются на скрытых скважинах. Совместные зависимости phi–k и связь эффективной толщины с NTG сохраняются, а не семплируются независимо без основания.

Категориальные фации вводятся только там, где поддержаны литологией/геологией. Нет обязательного обучения GAN по вымышленным «типовым каналам». Неопределённость интерполяции увеличивается вне наблюдаемого покрытия. Разные реализации сохраняют условность относительно наблюдений с их ошибками, а не обязаны проходить через каждое сомнительное значение точно.

## 7.3. Насыщенность и старт расчёта

Начальная фазовая конфигурация задаётся физически совместимым равновесием, контактами и зависимостями капиллярности/rock types с неопределённостью. Поздний So_log сравнивается с F на своей дате, а не штампуется в Soi. Доразработочный prior может использовать только наблюдения, действительно совместимые с этой эпохой и их погрешностями.

Если начало доступной истории не совпадает с началом разработки, требуется warm-up с неопределённой предысторией либо отдельный prior S0, совместимый с давлением/насыщением и предыдущим воздействием. Поле S0 не объявляется истинным Soi. Неограниченное независимое S0 в каждой ячейке не заменяет геологическую модель: используется коррелированная физически допустимая параметризация.

## 7.4. PVT, ОФП, WI, границы

PVT должны иметь заданные условия, положительные/физически совместимые Bo, Bw, Bg, Rs, вязкости и сжимаемости. Приоритет — данные целевого горизонта/сектора; затем документированные аналоги с обоснованным расширением uncertainty. Пользовательское начальное давление вносится после фиксации значения, источника, единиц и глубины; этот комплект не подменяет его чужой цифрой.

Sorw, Swc, Sgc, кривые kr и Pc задаются по rock types с ограниченным числом гиперпараметров. Эффективные множители k/WI и последствия ГТМ группируются по физическим объектам/событиям. Свободные коэффициенты на каждый скважино-месяц запрещены: они способны объяснить любой отклик без локализации.

Нужны неопределённые внешний обмен/аквифер и граничная поддержка, если сектор не замкнут. Их временная параметризация низкоразмерна и физически ограничена. Нельзя подогнать произвольный внешний фазовый источник в каждой ячейке, чтобы скрыть неверную геологию.

**Неполученные сведения:** подтверждённые секторные PVT/ОФП/Sorw в этом исследовании не найдены. Для синтетических capability-тестов разрешены явно учебные fluid models. Для реальных количественных объёмов требуется защищаемый prior; отсутствие источника фиксируется как gate, не как скрытый default.

## 7.5. Информативное подпространство без потери остатка

Высокоразмерный латентный геологический вектор разделяется на v и z_perp. Начальный ортонормированный KL/prior-базис строится без дорогостоящего LIS. Чувствительности и likelihood-informed уточнение [R10](SOURCES.md#r10) вводятся на development-пилоте, если дают измеримую пользу; полный LIS не является зависимостью первого сквозного запуска. Непрерывные физические/nuisance-параметры включаются в информативный блок или отдельные блоки с общей схемой плотности.

Стартовые диапазоны размерности v: 8–24 для малого опыта, 24–64 для пилота, 64–128 для исследования. Это не универсальные границы информации; изменение обосновывается learning/sensitivity/convergence curves, а не желанием вместить всю геологию в заданное число. **Все оставшиеся моды сохраняются**: q может предлагать их из p0(z_perp|v,s), но полная likelihood продолжает зависеть от них. Зануление остатка или замена его единственной средней реализацией запрещены.

Если residual directions заметно меняют posterior или карту, basis расширяется на development data; закрытый тест не используется для выбора ранга. Эффективность pCN/SMC и число частиц должны позволять исследовать остаток. Иначе публикуется ограничение вычислительной сходимости, а не уверенная карта.

## 7.6. Латентная мера и геология при изменении сетки

Prior и q определяются в одной **латентной** мере. Если v имеет стандартный нормальный prior, а физический параметр получается экспонентой/логистикой, в латентной log-density нельзя второй раз добавлять Jacobian физического renderer. Jacobian нужен при реальном переходе плотности между физической и латентной координатами; его место фиксируется в DensitySchema и проверяется аналитическим тестом. Плотность сплайновой трансформации NSF учитывается всегда в её собственной change-of-variables формуле.

Геологический renderer порождает поля K/phi/поверхности и согласованные WI/transmissibilities. Отдельные множители проводимости разрешены только для обозначенных экранов, контактов и структурной ошибки; не вводятся одновременно неограниченные независимые K и T каждой грани. Индекс случайной геологической реализации не становится классификационной меткой: дискретная head кодирует **семейство**, непрерывные поля — латенты.

При сгущении сетки coarse/fine получают согласованную underlying realization: сохраняются крупные латенты/поверхности, добавляются условные мелкие моды, восстанавливаются PV и проводимости. Инвентарь агрегируется консервативно; простая интерполяция So из грубой адаптации не является новым fine posterior. Полная likelihood на новой сетке требует нового пересчёта/коррекции. Веса NSF можно переносить только при совместимой семантике латентов; автоматический перенос q между произвольными сетками/секторами не обещается.

При разных G обучающие пары должны соответствовать известному условному prior p0(theta|G). Базовый вариант: взять разрешённый G/design, затем сгенерировать theta из его conditional prior. Если сначала симулируется скрытая геология, а затем её шумные статические наблюдения G, conditional renderer/latent coordinates должны быть согласованы с этим совместным законом. Нельзя использовать координаты безусловного генератора как будто это латенты другого conditional prior.

# 8. Прямой физический оператор

## 8.1. Физический класс: определённое правило выбора

**Единственный operational backend — JutulDarcy** [R01–R03](SOURCES.md#r01). Нефть–вода и black-oil являются конфигурациями одного адаптера; отдельные solver implementations не создаются.

Для `P0_VERIFY`/`P1_LOOP` используется штатная изотермическая oil–water система с гравитацией, положительными слабосжимаемыми свойствами и явными стандартными/пластовыми условиями. Это известная физика synthetic truth, не утверждение о реальном месторождении. Black-oil проверяется ранним малым capability-case, но не блокирует первый научный двухфазный цикл.

Для поля до основного корпуса обязательно принимается **PhysicsDecision**. Проверяется не только качество подгонки воды, но и изменение скрытой So/нефтяного объёма/ранга зон при допустимых PVT, начальном давлении, граничной поддержке, свободном газе и капиллярности. Отсутствие надёжного газового канала не доказывает отсутствия газа; обязательный black-oil с произвольными PVT также не гарантирует более точного результата.

| Результат проверки | Основная полевая конфигурация |
|---|---|
| Источники и sensitivity обосновывают несущественность газа для заявленного таргета | Нефть–вода с документированным диапазоном применимости |
| Газ существенно влияет и имеется защищаемый PVT prior | Black-oil, Rv=0; Sw+So+Sg=1, растворённый газ учитывается |
| Газ может существенно влиять, но доступные сведения не задают защищаемый диапазон | Сценарные отдельные результаты OW/BO; oil-specific количественный вывод остаётся ограниченным; требуется PVT/давление |

Сравнение начинается с парных моделей с общими геологией, controls и **одинаковым начальным стандартным нефтяным инвентарём**; физически согласованные PVT не заменяются независимыми случайными Bo/mu/Rs. Если результаты близки к границе решения, сравниваются ещё и условленные по одинаковой истории ансамбли. Несколько удобных forward runs недостаточны, чтобы доказать пренебрежимость газа во всём posterior.

Начальные инженерные допуски для этой проверки: PV-взвешенное различие So на report support ≤0,02 абсолютной доли, различие нефтяного инвентаря ≤5%, стабильность топ-зон/направления эффекта. Это проектные критерии, не свойства объекта; правило агрегирования по парным моделям и доверительные интервалы фиксируются на development, до закрытого теста. При недостаточно точном Monte Carlo или пограничном эффекте результат `UNRESOLVED`, а не автоматический OW-pass.

Капиллярность имеет такой же проверяемый статус. Для однородного Buckley–Leverett fixture Pc=0 допустимо. В полевом prior переходная зона и её стартовое равновесие должны быть согласованы с применяемым Pc. Если Pc исключается, первоначальная конфигурация проверяется на отсутствие искусственной длительной перестройки; нельзя создать капиллярное равновесие, выключить удерживающую его физику и принять перераспределение за разработку.

Относительные проницаемости: по умолчанию Corey oil–water по 1–3 обоснованным rock types; LET/другие кривые — structural stress и замена через PhysicsDecision при значимом влиянии. Параметры иерархические, `Swc+Sorw<1`, endpoints положительны, кривые физически допустимы. Для black-oil выбор трёхфазной интерполяции и gas endpoints фиксируется явно. Hysteresis не считается учтённой автоматически: при существенной смене направлений вытеснения требуется sensitivity/новый физический prior.

Compositional/thermal/chemical EOR не входят в основной класс. Если они необходимы для выбранного ГТМ, требуется новая физическая постановка, а не произвольная поправка насыщенности нейросетью.

## 8.2. Баланс и дискретизация

Концептуальный компонентный инвентарь при Rv=0:

`Mw_sc = PV * Sw/Bw`,
`Mo_sc = PV * So/Bo`,
`Mg_sc = PV * (Sg/Bg + Rs*So/Bo)`.

Для каждого компонента изменение инвентаря равно источникам минус отбор и чистый вынос через границы. Полный адаптер обязан согласовать зависимости PV от давления, Rs и стандартные условия с реализацией решателя. Эти формулы — контроль смысла, не инструкция писать свой finite-volume solver.

Фазовая скорость описывается законом Дарси `u_alpha = −K*(kr_alpha/mu_alpha)*(grad p_alpha − rho_alpha*g_vector)` в единой координатной конвенции. Передачи по граням, фазовое появление и нелинейное решение выполняет JutulDarcy.

Для сложной анизотропии/геометрии проверяется применимость штатной дискретизации: недостаточно выбрать TPFA по привычке. Выбор поддержанного метода закрепляется после сеточного benchmark. Up-scaling не может неконтролируемо стирать вертикальные экраны и прорывы.

## 8.3. Проверки до реальной инверсии

Нужны: single-cell PVT/фазовое появление; Buckley–Leverett в его области применимости; гидростатический покой; закрытая система без источников; well surface/reservoir conversion; двухслойное смешение и crossflow; событие открытия/изоляции; restart-equivalence; чувствительности против finite differences; сеточное/временное сгущение; ограниченный межсимуляторный контроль OPM при эквивалентной постановке на исследовательском этапе. Установка OPM не блокирует первый локальный цикл; аналитические и нативные physics tests обязательны с начала. Отличие discretization/physics в stress worlds проверяется и без второго operational backend.

Проектный ориентир относительной компонентной невязки: порядка 1e−5 или лучше на проверочных случаях после определения устойчивого нормировочного масштаба. Для мелких потоков нормировка включает абсолютный floor, чтобы не делить на почти нулевой инвентарь. Допуск уточняется на development benchmark и фиксируется до закрытых тестов; расхождение не скрывается ослаблением tolerance только для сложных posterior-частиц.

Физическая невалидность параметров, ошибка входных данных и численная несходимость — разные результаты. Несходимость сначала запускает зарегистрированную robust retry policy; её нельзя автоматически считать likelihood=0 без исследования, иначе posterior смещается к «удобным решателю» моделям.

# 9. Управления и оператор скважин

## 9.1. Исторические управления

Добывающая скважина получает **суммарный стандартный жидкостный расход**, а не два независимо предписанных фазовых расхода. Нагнетательная — стандартный расход воды. В JutulDarcy этому соответствуют `SurfaceLiquidRateTarget` и `SurfaceWaterRateTarget`; `TotalRateTarget` включает газ и не подменяет жидкость [R02](SOURCES.md#r02). Знаки native API, SI-пересчёт и плотность нагнетаемой смеси закрепляются тестом адаптера.

BHP рассчитывается как скрытая величина при rate control. Устанавливаются физически допустимые, но неопределённые при отсутствии измерений ограничения BHP/мощностей. Если реализация не может выполнить исторический расход при выбранных допустимых ограничениях, это несовместимость модели/условий, а не разрешение незаметно поменять наблюдаемое управление. Такие случаи возвращают диагностику, а после проверки — соответствующий likelihood/feasibility статус.

## 9.2. Время и месячные объёмы

Расход интегрируется по реальным длительностям месяцев, времени работы и событиям. Нулевые часы при положительном объёме — адресная неопределённость. Если внутри месяца известен только суммарный uptime, задаётся ограниченный набор временных распределений работы; месячный средний календарный расход не считается точным историческим расписанием без проверки чувствительности.

При добыче и закачке в одном месяце реконструируются интервалы переключения, совместимые с известными событиями/объёмами; неизвестный порядок остаётся сценарием. Роль строки не удаляет ненулевой поток другой фазы/назначения.

## 9.3. Оператор наблюдений

Для месяца интегрируются предсказанные surface Vo и Vw по всем подключениям и активным подынтервалам. Затем вычисляется fw. Snapshot в конце месяца не заменяет это интегрирование.

ГИС использует локальный геометрический support интервала и собственную дату; средняя So по интервалу не взвешивается автоматически фазовым притоком. Производственный и каротажный операторы принципиально различны.

## 9.4. Ошибка управлений: условная постановка

Основная статистическая задача **условна на сообщённую историю суммарных управлений**, а не является полной совместной моделью всех исходных счётчиков. При наличии оценки качества допускается латентная ошибка `e` с заранее заданным условным законом `p(e|U_obs,quality)` и `U_true=U_obs*exp(e−variance(e)/2)` для ненулевых потоков. Параметры ошибок групповые/коррелированные на физически разумном времени, не свободная поправка каждого месяца.

Vo и Vw входят в образование U_obs и fw, поэтому ошибки суммы и доли могут быть связаны. Перед выпуском нужна sensitivity к их условной ковариации; при существенной связи обновляется measurement model, а не объявляется независимость по умолчанию доказанной. Условное приближение отмечается в результатах.

**Запрещено:** задать Vo и Vw как управления, а затем считать их совпадение в likelihood; добавить как независимые likelihood-слагаемые fw, Vo, Vw, суммарную жидкость и накопленные объёмы из тех же измерений. Материальный баланс и накопленные объёмы прежде всего являются диагностикой, а не повторными измерениями.

## 9.5. Что означает conditioning на реальные controls

Принятые в работе управления могут зависеть от прошлых наблюдений оператора. Проект оценивает состояние **при заданной истории управления**, не причинный эффект закачки по наблюдательным данным. Если решения оператора основывались на недоступном нам давлении/геофизике, conditional модель может не использовать всю информацию; это ограничение обсуждается отдельно. Нельзя объявить кривые реальной эксплуатации независимым рандомизированным экспериментом.

Внутри synthetic studies политики, способные зависеть от прошлого synthetic watercut, используют только доступный префикс этого мира. Нельзя выбирать будущий дебит по скрытой истинной So, а затем скрыть этот способ построения управления от сравниваемых методов.

# 10. Вероятностная модель наблюдений

## 10.1. Требования

L является нормированной вероятностью наблюдений при заданной физической реализации. Она содержит шкалы ошибок и их нормировочные множители; произвольная weighted-MSE без статистической интерпретации не подменяет posterior likelihood. ML и baseline используют одинаковый набор наблюдений и одинаковую полную целевую плотность там, где сравниваются как posterior algorithms.

Ошибка включает измерение/интерпретацию и ограниченную residual discrepancy. Она не может свободно изменять пространственное состояние или фазовые потоки. Необъяснимая систематическая невязка инициирует проверку физики, подключений или prior, а не бесконечное увеличение sigma.

## 10.2. Базовый watercut likelihood

Выбран bounded observation model с робастными хвостами и временной зависимостью. Преобразование `g(f)=asin(sqrt(f))` имеет диапазон `[0,pi/2]`. Для каждой quality group заранее фиксируется сетка округления f, не более точная, чем измерение; её bins образуют **неперекрывающийся полный partition [0,1]**. Исходное точное значение сохраняется в таблице, для likelihood используется соответствующий bin `[a_t,b_t]`. Это корректно обрабатывает зарегистрированные 0 и 1 без искусственного clipping логита.

Для последовательности валидных наблюдений скважины:

`mu_t = g(fhat_t) + rho^Delta * (g(fobs_prev_center) − g(fhat_prev))`.

`Delta` — интервал в месяцах. При начале ряда/зарегистрированном reset режима корреляционный член равен нулю. Для rho используется ограниченный prior, по умолчанию неотрицательный; sigma зависит от quality и объёма/полноты учёта с ненулевым floor. Степени свободы nu и временная корреляция оцениваются на уровне небольшого числа групп, не каждой точки.

Условное скрытое наблюдение в g-пространстве имеет Student-t, усечённый на `[0,pi/2]`. Вероятность bin:

`L_t = {T_nu[(g(b_t)−mu_t)/sigma_t] − T_nu[(g(a_t)−mu_t)/sigma_t]} / {T_nu[(pi/2−mu_t)/sigma_t] − T_nu[−mu_t/sigma_t]}`.

Здесь T — CDF стандартного Student-t. Разности CDF вычисляются устойчиво в log-space. Предыдущий noisy bin используется только как часть явно заданной Markov observation model; состояние пласта им не корректируется. Синтетический noise generator генерирует эту же последовательность рекурсивно. В прогнозе неизвестный будущий fobs не подставляется вместо симуляции шумового процесса.

Когда `Vo+Vw=0`, fw отсутствует: ни 0, ни 1 не присваиваются. При пропусках Delta и mask сохраняются. Корреляции между скважинами/общими узлами учёта проверяются на residual diagnostics; обнаруженная существенная зависимость требует зарегистрированного группового noise model. До этого покрытие считается условным относительно выбранного приближения.

## 10.3. ГИС

Числовой So_log сравнивается с предсказанным `H_log[X(t_log)]` как bounded noisy observation с групповым смещением интерпретационной эпохи/скважины. Геологическое и методическое смещения не могут оцениваться неограниченно одновременно: нужен anchoring prior и sensitivity к нему. Датировка задаётся дискретной quadrature по допустимому временному интервалу, likelihood маргинализуется как взвешенная сумма, а не выбирается самая удобная дата.

При неразрешённой семантике «нефть или углеводороды» существуют отдельные гипотезы оператора So и So+Sg с prior и posterior weights. Сомнительные нули/844 и другие QC-fail значения не становятся target. Категории Н/В используются как слабое отдельное наблюдение только при отсутствии численного значения, чтобы не считать одну интерпретацию дважды.

Все интервалы одной скважины не считаются независимыми высокоточными замерами: общие интерпретационные biases входят в theta. Разрешение логового support не переносится автоматически на межскважинный объём.

## 10.4. Другие наблюдения и ограничения

Газ исключён из основной L до подтверждения единиц и независимости его измерения. При восстановлении канала задаётся отдельный оператор стандартного газа с растворённой составляющей, а не Sg=gas/oil. Давление включается только после появления независимого датированного замера с глубиной и типом.

Физические ограничения (допустимые свойства, насыщенности, BHP feasibility) входят в поддержку модели. Сходимость решателя сама по себе не является физическим ограничением. «Exact likelihood» далее означает вычисление L через полный принятый F, не утверждение точности физики мира или метрологии исходных CSV.

# 11. Центральная ML-модель

## 11.1. Что она получает и выдаёт

Вход: разрешённая статическая геология и её uncertainty descriptors; геометрия скважин/слоёв; последовательности liquid/injection controls, fw и masks; роли, uptime, события/неопределённость подключений; даты и длительность истории; известные параметры постановки, но не истинные скрытые поля тестового мира.

Выход: нормированная условная плотность **параметров физической модели**, из которых симулятор получает So. У NSF нет независимого raster-head, выдающего окончательную карту в обход физики.

Нельзя подавать модельное давление как будто оно наблюдалось; идентификатор скважины используется для связи таблиц, не как embedding, позволяющий запомнить объект. Признаки приводятся к относительной геометрии/физическим масштабам; абсолютная координатная информация допускается только как объявленный geological context, не идентификатор synthetic seed.

## 11.2. Пространственно-временной кодировщик

Основной контекст — graph-temporal сеть по скважинам. Узлы содержат временные признаки скважины и интервальную геологическую сводку. Рёбра задают **потенциальную**, а не доказанную связь: расстояние, совместные слои, относительную глубину, возможные подключения и геологические барьеры. По умолчанию граф разреженный: ближайшие 8–16 кандидатов на слой и дополнительные геологически необходимые связи. Это стартовые настройки, проверяемые на development set.

Временное кодирование и обмен между скважинами чередуются **до финального pooling**, чтобы модель могла учить запаздывания реакции на закачку. Основной блок: causal dilated temporal convolutions → edge-conditioned graph attention → residual/normalization. Стартовая research-конфигурация — 3 блока, ширина 128, 4 attention heads, temporal dilations до 32; masked pooling образует контекст размерности 256. Более длинная история кодируется иерархически по временным окнам с передачей границ/summary, без потери порядка событий. Это начальный дизайн для benchmark, не окончательные гиперпараметры.

Порядок скважин не влияет на ответ: проверяется permutation equivariance/invariance. Появление новой скважины, отсутствие события, настоящий нулевой поток и missing имеют разные masks. При as-of режиме свёртки и pooling видят только префикс. Будущая геология/наблюдения не проникают через нормализатор, выбор соседей по будущему отклику или feature engineering.

Геологический контекст передаёт условный prior и измерения с support, а не полную истинную permeability map synthetic мира: сеть не должна обучаться в информационном режиме, недоступном на поле. Отдельный эксперимент с известной геологией разрешён как upper-bound diagnostic.

### 11.2.1. Размер сети и переносимость

Начальный малый профиль использует тот же вид блоков, но ширину 64, два graph-temporal блока и контекст 128. Основной research ориентир выше — не обязанность с первого запуска. Минимальный граф реализуется обычными dense PyTorch tensor operations с маской допустимых рёбер; для десятков скважин не нужна CUDA-only sparse extension. Переход к sparse library возможен после benchmark.

Модель `summary + NSF` и `temporal-set + NSF` являются обязательными representation baselines на development. Graph сохраняется в final configuration только при измеримой пользе по заранее выбранной state/calibration/cost метрике; выбор делается **до** закрытого теста. Отсутствие пользы graph не удаляет ML: плотность inverse parameters по истории остаётся обучаемой.

Первичная амортизация относится к одному согласованному классу сектора/геологических латентов и его history cutoffs. Перенос на новую геометрию/другой basis требует проверки conditional priors, размеров и calibration. Нельзя обещать универсальную готовую сеть для произвольного месторождения. Encoder weights можно использовать как initialization, но q и её density переутверждаются для нового model_id.

## 11.3. Conditional NSF и дискретные гипотезы

NSF использует обратимые rational-quadratic spline coupling transformations [R04](SOURCES.md#r04). Research-старт: 8–12 coupling layers, 8 bins; малый профиль — 6 coupling layers по COMPUTE_PROFILES.md. Base density нормальная; ограничения ширины/высоты/производных положительны, хвосты линейные. NSF выдаёт unconstrained латенты v; физические bounds обеспечивает renderer. Jacobian spline-flow входит в q(v), а Jacobian физического transform добавляется только при действительной смене меры согласно §7.6. Плотность вычисляется через change of variables, без ODE для density.

Дискретная часть s имеет категориальную head. При нескольких связанных гипотезах это autoregressive factorization в фиксированном порядке «семейство → скважина → временное окно» с масками допустимых альтернатив. Совокупная вероятность известна как произведение условных вероятностей; запрещены скрытые rejection rules без учёта нормировки.

Полное предложение:

`q_phi(s,v,z_perp | C) = q_phi(s | C) * q_phi(v | s,C) * p0(z_perp | v,s,G)`.

Здесь C — контекст. Для начальных хорошо наблюдаемых подключений s может быть детерминирован; неизвестные альтернативы нельзя выключить только из-за трудности обучения. Плотности существуют в общей латентной схеме каждого семейства; размерности разных семейств учитываются явно, а не складываются как плотности на одном фиктивном пространстве.

Физический renderer из латентов в поля может быть неинвертируемым: требуется известная плотность **латентов**, а не аналитическая плотность каждого геологического растра. Остаток z_perp сохраняется и входит в полную физическую likelihood.

## 11.4. Обучение

Синтетическая пара содержит известные theta, G, U, noisy Y и true states. Основной objective — negative log-likelihood дискретного и информативного латентного блока. При выборке theta из p0 это обычная posterior-estimation задача; NLL не заменяется обучением на MAP-оценках реального history match.

При целевой/адаптивной генерации из известного r_j(theta|design) используются корректирующие веса `p0/r_j` или строгий эквивалентный алгоритм. В основной реализации выбран importance-weighted NLL; смеси раундов имеют явные доли и proposal densities. Нельзя без коррекции смешать prior simulations и близкие к реальному posterior модели, а затем интерпретировать q как prior-trained posterior. Методическая причина обсуждается в [R08](SOURCES.md#r08).

Высокая дисперсия весов требует расширить defensive sampling и пересмотреть генерацию. Weight clipping, если исследуется, маркируется как смещённый training objective; финальная коррекция всё равно обязательна, а scientific results указывают режим. Closed test не используется для выбора нового simulation proposal.

Дополнительное обучение прямого forecaster watercut не является обязательным loss. Базовая сеть оптимизирует ровно плотность inverse parameters; физическая достоверность и So-метрики проверяются downstream. Это уменьшает конкуренцию несогласованных задач.

### 11.4.1. Backend и точность proposal

Обучение: PyTorch CPU Float32 по умолчанию; MPS Float32 разрешён после unit/gradient/performance tests конкретных операций. PyTorch MPS не поддерживает Float64 [R27](SOURCES.md#r27). Основная оценка likelihood, prior, SMC weights и физический solver работают CPU Float64.

Для operational SMC создаётся **frozen CPU Float64 copy** NSF/checkpoint; conditioning context вычисляется и фиксируется в том же backend/dtype. И sampling, и log_prob, и их gradients используют именно эту копию. Нельзя семплировать MPS Float32-модель, а оценивать плотность как будто это другая Float64-модель без проверки согласованности. Переход MPS→CPU — отдельный test, не предположение о побитовой идентичности. На маленькой сети CPU может оказаться быстрее; выбор определяется benchmark, а не названием GPU.

Во время SMC dropout выключен; batch-dependent training statistics фиксированы. Если используется ensemble нескольких checkpoint, q является нормированной смесью с известными весами и logsumexp плотностью. Выбирать лучший seed по closed test запрещено. Первый цикл может иметь один seed, research — несколько независимых обучений.

## 11.5. Почему не FMPE по умолчанию

Нормированная плотность нужна многократно при SMC/MH. NSF выбран для прозрачной change-of-variables density, а не потому, что FMPE не умеет плотность или заведомо хуже [R04–R06](SOURCES.md#r04). Замена на FMPE требует benchmark mode coverage, состояния и полной стоимости density/correction. Это одно альтернативное ADR, не обязательный параллельный проект.

# 12. Синтетические данные и наблюдаемость

## 12.1. Зачем синтетика

Синтетическая разработка даёт известные theta и поле So во всех ячейках и временах. Поэтому можно проверить, восстанавливает ли метод состояние, а не только воспроизводит историю скважин. Эта истина верна **в симулированном мире**. Она не превращает реальную So в наблюдаемую и не доказывает переносимость автоматически.

Синтетика появляется в **E01**, малая inverse-задача — в **E02**, а весь цикл с ML и физической коррекцией — в **E03**. После подключения реального пилота E07 повторяет сквозную проверку в полеподобном режиме. Основной корпус создаётся в E08, только после этих двух промежуточных результатов. Подробности — §22 и STAGES.md.

## 12.2. Генеративный процесс

Для каждого world: выбрать structural family и геологические гиперпараметры; сгенерировать физически допустимые поля; сформировать разреженные геологические наблюдения с датами/ошибками как на поле; выбрать/воспроизвести controls и подключения; рассчитать JutulDarcy; сформировать noisy observation channels, masks и missingness; сохранить hidden truth отдельно от разрешённого ML context.

История реальных управлений может служить design template, но реальные фазовые наблюдения не используются для тайной настройки truth test cases. Разнообразие включает режимные изменения, роли, неоднородность, PVT, начальную/граничную поддержку, пропуски и неопределённые подключения. Физически невозможные независимые комбинации параметров не образуют «широкий prior».

Реальные статистические distributions строятся только по разрешённой training/development части. Корпус, состоящий из шумовых копий единственной лучшей реальной адаптации, запрещён как независимая оценка точности.

## 12.3. Разбиение

Единица разбиения — **полный геологический мир / его семейство производных**, не строка, timestep или snapshot. Все префиксы, шумовые повторы, альтернативные управления и близкие производные одного базового realization seed находятся в одном fold. Realizations с общим parent seed и почти одинаковой структурой группируются. Скалеры, variograms и basis fit не видят test.

Наборы: training; development/early stopping; locked in-distribution test; locked stress/OOD test. Stress worlds включают более мелкую сетку, неучтённый характер границ, другой тип допустимой ОФП/капиллярности, иной рисунок связности и ошибки подключений. Отличия фиксируются заранее, а не выбираются после просмотра удачных карт.

## 12.4. Масштаб и вычислительная реалистичность

Количество симуляций задаётся профилями COMPUTE_PROFILES.md и измеренной стоимостью. Начало: 128 → 256 → 512 независимых малых training worlds, не тысячи полносекторных расчётов. Следующие уровни: полеподобный пилот 256 → 512 → 1 024; research 1 024 → 2 048 → 4 096 и далее лишь по learning curves. Это лестницы допустимого расширения, а не обязательный заказ всех уровней. Validation/test/reference/inference считаются **дополнительно** и включаются в полный budget.

Один world может давать несколько cutoff views/noise replicas, но они не увеличивают количество независимых геологических миров. Разделение parent-level остаётся обязательным. Corpus хранится на диске; в память загружается minibatch, не весь набор траекторий.

Малые exploratory diagnostics используют 8–16 evaluation worlds и не доказывают точное coverage. На дешёвых reduced cases исследовательская калибровка планируется порядка 100 независимых миров с известной истиной; на полносекторном confirmatory test начальный ориентир 12–24 мира с анализом статистической мощности и расхода до запуска. Допуски coverage интерпретируются вместе с межмировой/биномиальной неопределённостью. SBC сырого q не подменяет проверку всей SMC-системы.

Сохраняются theta, разрешённые well histories, design/G/masks и So на заранее выбранных датах. Для inverse-density training сам полный So-cube не является обучающим таргетом; его можно хранить только на evaluation/diagnostic subset, сохранив точную возможность воспроизведения. Для тестовых миров truth и restart сохраняются отдельно от ML context. Каждый внутренний Newton/time-substep cube в долговременный corpus не записывается; это не отменяет временного хранения/checkpointing, нужного adjoint.

## 12.5. Предварительный observability test

До массового обучения проверяются как минимум: разный So при близком history match; влияние неизвестного давления/PVT; неоднозначное распределение притока между двумя слоями; неизвестная поздняя изоляция; удалённая от фонда нефтенасыщенная зона; влияние остаточных геологических мод; разная масштабность публикации.

Если на нужном support состояние не различимо даже хорошим non-ML inference, нельзя обещать, что большой encoder решит отсутствие информации. Возможны обоснованное укрупнение support, получение измерений или выпуск карты широкой uncertainty. Простая замена таргета на watercut запрещена.

# 13. Физически скорректированный posterior: SMC

## 13.1. Начальное defensive proposal

Для конкретной задачи q обученной сети фиксируется на весь bridge. Начальная плотность:

`r(theta) = (1−epsilon)*q_phi(theta|C) + epsilon*p0(theta|G,U_obs)`.

Стартовое epsilon=0,10; выбор на development cases и sensitivity обязателен. Prior-компонента сохраняет поддержку, даже если сеть пропустила моду. Ненулевая поддержка не гарантирует её нахождения конечным числом частиц.

Каждая частица имеет theta, полный forward result либо диагностированный статус, log p0, log q, log r, log L и provenance. Смешанные дискретно-непрерывные плотности оцениваются относительно согласованной меры; нулевой prior означает физически/модельно исключённый случай, а не «сеть не видела таких данных».

## 13.2. Мост и веса

Выбран мост:

`pi_beta(theta) ∝ r(theta)^(1−beta) * [p0(theta)*L(theta)]^beta`,
`beta: 0 → 1`.

При переходе от beta_old к beta_new:

`log w_increment = (beta_new−beta_old) * [log p0 + log L − log r]`.

ESS нормированных importance weights определяется как `1/sum_i W_i^2`. На beta=0 log target явно равна log r, чтобы избежать неопределённого `0*(-Inf)` у невозможных частиц. Если все веса обнулились, возвращается `NO_TARGET_SUPPORT` с диагностикой; веса не заменяются равномерными для продолжения.

Это **не** обычное темперирование только likelihood из произвольного q. Без члена prior/proposal финальное распределение было бы смещено.

Для нормализованных текущих весов W и a_i=exp(delta_beta*ell_i), ell_i=log p0+log L−log r, используется `CESS = N*(sum W_i*a_i)^2/(sum W_i*a_i^2)`, рассчитываемый устойчиво через logsumexp. CESS при delta_beta=0 равен N. Стартовая цель — 0,8N; последовательность beta монотонна и заканчивается строго на 1. Следующая beta выбирается по conditional ESS; resampling выполняется при зарегистрированном пороге, по умолчанию ESS < 0,5N. На шагах beta не требуется новый forward для неизменной частицы: L кэшируется по полному model hash. Для `P1_LOOP` число particles начинается с 32 и затем 64; для пилота — 64–128; для research — 128–512 и больше по сходимости. Небольшой отладочный ensemble не получает право на полевой выпуск только потому, что завершился. Порог качества определяется convergence/MC uncertainty, а не красивым растром.

## 13.3. Rejuvenation

Нужна смесь инвариантных относительно **текущей** pi_beta переходов:

- независимые глобальные предложения из r с полным Metropolis–Hastings отношением;
- локальные предложения информативных непрерывных параметров; MALA с проверенным adjoint-gradient там, где оператор дифференцируем, иначе корректный random-walk kernel;
- pCN геологического остатка относительно его гауссовской опорной меры;
- локальные/блочные переходы дискретных семейств и completion hypotheses с известной вероятностью обратного предложения.

Вероятности выбора rejuvenation kernels и их настройки фиксируются на зарегистрированном уровне/семействе; state-dependent selection требует учёта соответствующих вероятностей в MH. Неудачный gradient означает диагностированный отказ данного предложения, а не бесконтрольную подмену MALA другим переходом с иным законом. У g(f)=asin(sqrt(f)) производная проблемна на границах 0/1; там запрещено молча вводить clipping, меняющий target. Используются проверенные предельные производные/корректный gradient-free kernel и отдельные edge-case tests.

По умолчанию семейства пилота используют согласованные латентные координаты одинаковой размерности. Если семейства имеют разные размерности, глобальный переход предлагает **полную** новую частицу из нормированной mixed-space r; локальное переключение требует явно выведенного reversible-jump/augmentation перехода. Простая смена category при сохранении несовместимого вектора запрещена.

pCN не принимает автоматически по отношению L на всех beta: применяется полное отношение target и proposal/reference measure. Упрощённое likelihood-only отношение допустимо только когда соответствующее сокращение математически верно. Аналогично transformations физических bounds и asymmetry MALA учитываются явно.

Adjoint уменьшает стоимость градиента, но не обязателен для корректности SMC. Смена control branch и фазовое появление могут давать трудные производные; они проверяются. Нельзя игнорировать MH-correction, выдавая optimizer steps за posterior sampling.

### 13.3.1. Градиент месячной likelihood без общего Python–Julia autograd

Первый полный локальный цикл использует корректные gradient-free MH/pCN переходы. Это тот же posterior и тот же SMC, а не иной метод. Adjoint-assisted MALA вводится после прохождения monthly-objective gradient gate; full HMC/NUTS не являются обязательной подсистемой.

Для research используется chain rule. Пусть h(theta) — вектор месячных фазовых интегралов и прогнозов ГИС, а ell(h,psi)=log L — CPU observation model. Сначала при текущей theta рассчитывается `a = d ell / d h`, включая нормировку, AR-зависимости, date marginalization и общие biases. Затем Julia adjoint дифференцирует **линейный функционал** `J(theta)=a^T h(theta)` с зафиксированными на этой оценке коэффициентами a. Его градиент равен `(dh/dtheta)^T a`; прямые производные по noise psi, prior, q и преобразованиям добавляются отдельно.

Для месячного фазового объёма это `sum_(well,month,phase) a_(w,m,alpha) * integral_month q_(w,alpha) dt`. Для ГИС — соответствующие state sensitivities на датах quadrature. Так не требуется дифференцировать SciPy CDF внутри Julia, но нужна проверенная реализация интегральных/cross-time зависимостей. Нативная instantaneous-MSE из примера history matching не подменяет этот функционал [R31](SOURCES.md#r31).

Принятые timesteps/events и возможность воспроизвести промежуточные states входят в gradient contract. При адаптивных ветвлениях/появлении фазы градиент проверяется отдельно. Если нужный sensitivity не поддержан, используется корректный gradient-free kernel; отсутствующий adjoint не компенсируется подстановкой иной likelihood. Для сравнительных MAP-экспериментов такой статус фиксируется как ограничение, а не называется выполненным adjoint baseline.

## 13.4. Структурная неопределённость

Поскольку s входит в theta, posterior веса геологических/граничных/операционных гипотез получаются совместно. Если расчёты разбиты по семействам, для объединения нужны корректные evidence estimates и prior weights. «По 100 реализаций каждого семейства, значит все семейства равны» запрещено.

Изменение q во время незавершённого bridge запрещено без математически корректной adaptive SMC схемы. По умолчанию новое обучение — между завершёнными раундами, новый frozen r — новый bridge. История proposal densities сохраняется.

### 13.4.1. Новая дата и повторное использование расчётов

Новый cutoff/новая сетка/изменённые noise parameters меняют целевой posterior. Предыдущие состояния служат cache/restart только для **той же** физической частицы, согласованной предыстории и версии solver. Нельзя заменить первые десятилетия истории restart средней модели для всех новых theta. Специальная online state assimilation с иным распределением перехода не входит неявно в эту спецификацию.

### 13.4.2. Ограничение бюджета не меняет математику

При исчерпании wall/forward/memory budget SMC сохраняет particles, веса, beta, genealogy, RNG, q-hash и статус `INCOMPLETE_BUDGET`. Если beta<1, это промежуточное распределение, **не posterior**; нельзя назвать его конечным, принудительно заменить beta на 1 или убрать поправку r. При beta=1, но провале convergence, статус `POSTERIOR_NOT_CONVERGED`. Возобновление продолжает ту же последовательность; завершённые дорогие likelihood сохраняются.

## 13.5. Что означает готовый posterior

Обязательны replicated starts, сопоставление независимого prior-start inference на малых cases, контроль частиц/мод, doubling-budget check и Monte Carlo uncertainty интересующих агрегатов. Большой ESS после resampling сам по себе не доказывает mode coverage. Несколько одинаковых потомков одной частицы — не независимые геологические объяснения.

Для каждой конечной частицы существуют согласованные state/restart полного F; веса нормализованы. Самонормированные конечные importance estimates имеют Monte Carlo error и могут иметь finite-sample bias. Нельзя писать «точный posterior» без этих оговорок. Pointwise mean/quantile cube может не являться физически реализуемой отдельной траекторией: вместе с ним сохраняются representative simulated particles.

# 14. Научная валидация и критерии успеха

## 14.1. Baselines

**B0 Static prior:** та же условная геология без динамического conditioning. Показывает вклад истории, не является единственным конкурентом.

**B1 Exact-target prior-start SMC:** та же p0, L, физика, residual dimensions и data; старт из prior, без learned q. Это главный контроль, отделяющий эффект предложения от изменения целевой модели.

**B2 Multi-start adjoint MAP:** те же данные/prior/likelihood, многозапусковый поиск мод. Сравнивается как point estimator и по найденным объяснениям; один MAP не выдаётся за неопределённость. Laplace/другой uncertainty method, если вводится, документируется отдельно.

**B3 Localized ES-MDA:** полноценный настроенный ансамблевый history matching, а не заведомо малый неподготовленный ensemble [R13](SOURCES.md#r13). Стандартный ES-MDA использует гауссовское приближение ошибок в выбранном преобразовании; поэтому при bounded Student-t L это **практический approximate baseline**, а не алгоритм, гарантированно имеющий тот же posterior. Строгое same-target утверждение относится к B1/B2. Для ES-MDA дополнительно проводится Gaussian-compatible control experiment, где сравниваемые методы используют одну observation model. Локализация/инфляция подбираются только на development.

**B4 Summary-NSF / temporal-set NSF:** тот же conditional density family и та же SMC-коррекция, но без graph-temporal представления. Это ML-baseline, отделяющий вклад encoder от самого наличия learned proposal.

Все baselines используют одинаковую разрешённую информацию, геологический support и удержанные тесты. Нельзя дать ML известную геологию/подключения, а baseline — неизвестные.

## 14.2. Метрики скрытого состояния

Основные: PV-weighted MAE/RMSE So на установленном support; CRPS для scalar zone states/инвентаря; покрытие и ширина Q05–Q95; ошибка N_rem и N_above_Sor; восстановление пространственного ранга перспективных зон и decision regret на synthetic truth. Отдельно измеряется error в слабо наблюдаемых участках, а не только рядом со скважинами.

Для класса «перспективная зона» пороги определяются физическим сценарием/предварительным критерием, не по test labels. Метрики карты считаются по world/sector единицам; тысячи соседних ячеек не считаются тысячами независимых экспериментов. Доверительные интервалы сравнения — paired bootstrap/иерархический анализ на уровне независимых миров.

Обязательны SBC/rank diagnostics на малых мирах и проверка repeated coverage всей корректированной системы, а не только q [R12](SOURCES.md#r12). Калиброванный, но практически не сузившийся prior не считается полезной локализацией.

## 14.3. Проектные критерии и границы научных утверждений

Сохраняется основная метрика SPEC 3.0: **PV-weighted MAE текущей So** на зарегистрированном report support, с последующим равным усреднением по независимым truth worlds. RMSE обязателен как дополнительная метрика крупных ошибок; ранний exploratory опыт может использовать RMSE как диагностический ориентир. Подмена основной MAE на RMSE после просмотра результатов запрещена.

Внутри мира `MAE_w = sum_A PV_truth_A * abs(So_est_A − So_truth_A) / sum_A PV_truth_A`. Сначала truth и estimate приводятся к одному support; оценка состояния — posterior weighted mean, если протокол не зафиксировал иной estimator до теста. Truth weights не заменяются predicted PV. При положительном truth PV и отсутствии оценимого состояния зона помечается failure, а не удаляется ради метрики. Геометрические failures публикуются отдельно и блокируют положительный общий claim без заранее заданного правила оценки.

Следующие пороги — проектные критерии, а не подтверждённые свойства объекта. E08 записывает их в `ResearchProtocol` вместе с точными агрегаторами, неопределённостью сравнения и основаниями применимости. Изменение порогов требует ADR и новой версии протокола до закрытых тестов.

| Проверяемый результат | Критерий | Допустимое утверждение |
|---|---|---|
| C_STATE: улучшение реконструкции So | Средняя MAE ниже лучшего сопоставимого non-ML метода минимум на 10%; нижняя граница paired 95% CI относительного улучшения > 0; RMSE/CRPS и калибровка приведены без сокрытия ухудшения | ML улучшил оценку So при указанном бюджете |
| C_CAL: достоверность uncertainty | Для nominal 90% intervals ориентир coverage 85–95%; для 50% — 45–60%; отдельно width, SBC и world-level uncertainty покрытия всей скорректированной системы | Калибровка поддержана на проверенном классе миров; при недостаточной мощности — INCONCLUSIVE |
| C_VOLUME: нефтяной инвентарь | Для N_rem и N_above_Sor отдельно: median absolute relative error ≤15%, q90 ≤30% на ID worlds; знаменатели/floors и абсолютная ошибка фиксируются заранее | Инвентарь воспроизводится с указанной точностью в synthetic study |
| C_LOCALIZATION: поиск перспективных зон | При бюджете выбора top 20% допустимой площади захватывается ≥70% истинного нефтяного объёма зарегистрированных аномалий и минимум на 10 процентных пунктов больше лучшего non-ML baseline; paired 95% CI прироста >0 | ML улучшил именно локализацию перспективных зон |
| C_FIELD: косвенный полевой контроль | Held-out log predictive density не хуже лучшего baseline в одинаковом информационном режиме, calibration не ухудшается сверх зарегистрированного допуска | Полевые наблюдения согласуются с применением метода; ошибка истинной So поля остаётся неизвестной |
| C_COST: вычислительная польза | Accuracy–cost curves при равном online бюджете и при равной целевой точности; отдельно cold-start и проверенная амортизация | Ускорение/выгода только в том режиме, где это подтверждено |

Для C_CAL недостаточно попадания единственной оценки coverage в диапазон: число миров и интервалы неопределённости должны позволять содержательный вывод. Calibration на 100 дешёвых мирах не приписывается автоматически сложному сектору. Полезная ширина интервала фиксируется по инженерной задаче. Coverage 90% intervals <80% на ID confirmatory, систематический SBC skew, потеря мод или несходимость запрещают выпуск номинально калиброванных локальных карт; возможен диагностический продукт с явным отказом от количественной оценки.

Для C_LOCALIZATION аномалии создаются физически по §14.5.1 до forward, а их truth masks, допустимая область выбора, правило ранжирования и tie-break фиксируются до теста. При разных размерах зон используется бюджет площади, а не число клеток. Capture — доля истинного N_above_Sor в зарегистрированных аномалиях, попавшая в выбранные зоны. Миры без такой аномалии участвуют в false-positive/abstention тесте; знаменатель 0 не заменяется произвольным epsilon. Для разных размеров аномалий дополнительно измеряются смещение центра, восстановленная амплитуда и пространственное размытие. Хорошая средняя MAE без C_LOCALIZATION не является доказательством качества выбора зон.

Для C_VOLUME в мирах с почти нулевым инвентарём используются заранее заданный физический floor и абсолютная ошибка; такие миры не исключаются после просмотра результатов. Для C_FIELD протокол задаёт единицу нормировки log score, paired uncertainty и non-inferiority margin (по умолчанию 0); нижняя граница 95% CI разности должна быть не ниже минус margin. Недостаточная точность сравнения означает INCONCLUSIVE. Дефицит реальных наблюдений нельзя компенсировать synthetic RMSE.

Engineering feasibility ориентир: агрегированная So MAE ≤0,05 абсолютной доли на подтверждённом support. При невыполнении C_STATE допустим efficiency-only результат; при невыполнении C_LOCALIZATION остаётся отдельный вывод о средней реконструкции. Для сильного заявления об улучшении локализации нужны C_STATE, C_CAL и C_LOCALIZATION; количественный вывод об объёмах дополнительно требует C_VOLUME, перенос на поле — C_FIELD и gates данных/физики. Отрицательный результат допустим; выбирать из MAE, RMSE или capture удобную замену primary claim после теста запрещено.

Research сравнение включает минимум три независимых seed обучения и replicated inference starts с анализом изменчивости. Все зарегистрированные worlds и failures отражаются в отчёте. Выбор архитектуры и настройка **всех** baselines завершаются на development до открытия E11; frozen protocol не означает запрета корректной development-настройки методов.

## 14.4. Честный бюджет

Сравниваются как минимум два режима:

`Cold-start cost = corpus simulation + preprocessing + ML training + inference + verification`.

`Amortized cost per task = shared development/training cost / K + online inference cost`.

K — фактически предусмотренное/проверенное число независимых задач: новые секторы, новые состояния или сценарии. Нельзя объявить огромный воображаемый K, чтобы скрыть стоимость обучения. Исторические префиксы одной реализации не становятся независимыми научными test cases, хотя могут быть отдельными operational queries.

Учитываются core-hours, GPU-hours, wall time, память, число полных forward, adjoint, restart, failed/retry и density evaluations. Forward-equivalent cost для adjoint определяется измерением, не утверждается универсальным множителем. Online budgets, например 512/2 048/4 096 forward-equivalent calls, выбираются после runtime benchmark. Публикуются accuracy–cost curves, а не одна удобная точка.

Равный online budget при уже обученной сети отвечает вопросу operational amortization. Он не доказывает, что ML выгоднее для единственного cold-start месторождения. Оба вывода разделяются.

## 14.5. Ablations и отрицательные контроли

Обязательный минимальный набор: full method; q без физической коррекции; без динамического контекста; без межскважинного обмена; без событий/с ошибочно фиксированными подключениями; truncation геологического остатка; отсутствие газовой неопределённости на gas-sensitive worlds. Последние варианты — диагностические ablations, не разрешённые production shortcuts.

Negative control: перестановка/сдвиг истории нагнетателей при сохранении маргинальных распределений; сеть должна терять именно полезность связанного динамического сигнала. Сравнение с известной истинной геологией/давлением — upper-bound информационного режима, не baseline «на равных».

Нужен out-of-family test: иначе сеть может научиться инвертировать генератор, не справляясь с допустимым отличием реальной физики. Хороший ID test не отменяет OOD fail.

### 14.5.1. Честные anomaly/observability tests

Для проверки локализации аномалия создаётся до forward расчёта через геологию, начальные условия и историю вытеснения. Нельзя вручную повысить So в конце расчёта, оставив прежнюю добычу/баланс. Успешный тест с известной идеальной геологией считается верхней границей и не заменяет случай с неизвестными K/PV/подключениями.

Уточнение posterior может сдвигать среднее, не уменьшая дисперсию; малый сдвиг среднего также не означает отсутствия информации. Статус prior-dominated не присваивается по одному порогу mean shift или одной variance ratio. На синтетике проверяются coverage/bias/information gain, на поле — sensitivity и альтернативные объяснения; решение принимается по зарегистрированной комбинации.

## 14.6. Реальная валидация

Rolling cutoffs: исходные кандидаты 2010/2015/2019 с горизонтами 12/24 месяца; окончательные срезы выбираются по доступности и фиксируются до обучения. Для blind new-well оценки скрывается весь запрещённый пакет будущего бурения/ГИС, а не только строка дебита. Отдельно можно оценивать режим, где геология места уже известна; он называется иначе.

Проверяются будущий phase response, время прорыва, распределение watercut, интегральные объёмы при заданных controls, согласованность датированных поздних наблюдений и устойчивость к удалению отдельных скважин. Просмотр будущей МЭР для корректировки prior до теста запрещён.

Без независимой текущей So нельзя измерить истинный RMSE реального поля. Полевой backtest — проверка косвенной согласованности. Уверенность в скрытом состоянии формируется совместно с synthetic state tests, sensitivity и физической диагностикой, но остаётся условной относительно модели.

# 15. Пространственные продукты и неопределённость

## 15.1. Минимальный комплект карт

Для каждого слоя/агрегата и даты выпускаются: weighted mean и Q05/Q50/Q95 So; N_rem и N_above_Sor; kr_o/мобильность как дополнительный диагностический канал; изменение относительно собственного S0/Soi с указанием определения; posterior uncertainty; prior→posterior contraction; structural-family sensitivity; data coverage/observability support; статус допустимости интерпретации.

Q05/Q95 обозначают обычные нижний/верхний квантили CDF. Не используются неоднозначные нефтегазовые обозначения P90 без явной конвенции. Для объёма зоны сначала суммируется объём **внутри каждой частицы**, затем берутся квантили распределения. Сумма поклеточных квантилей не равна квантилю объёма зоны.

### 15.1.1. Общий пространственный support при разных реализациях

Report zones задаются в общей геометрии. Внутри каждой частицы расчётные ячейки пересекаются с ними консервативным оператором. Для zone A `So_A = sum(PV_intersection*So)/sum(PV_intersection)`; нефтяной инвентарь считается отдельно. Если PV_A=0, So_A отсутствует, а инвентарь равен нулю. Выводятся вероятность присутствия коллектора и насыщенность **при его наличии**; отсутствие коллектора не изображается как So=0.

При разных сетках truth и estimate сначала приводятся к одному report support, затем считаются ошибки. Порово-объёмное усреднение So не эквивалентно арифметическому среднему всех ячеек. Межчастичные квантили и наличие/отсутствие коллектора имеют явно разные знаменатели. «Локальный ESS карты» не вводится без математического определения: глобальные particle weights, genealogy и MC error зон — разные характеристики.

## 15.2. Информационная поддержка

Для zone A оценивается, насколько динамика сузила распределение соответствующего состояния/объёма относительно prior, и насколько вывод меняется при альтернативных допустимых моделях. Простая variance contraction без bias/coverage не доказывает правильность. Нужно сопоставление с synthetic observability и реальные residual/OOD diagnostics.

Статусы: **supported**; **weakly supported**; **prior-dominated**; **unresolved/model-sensitive**; **no valid geometry/data**. Их критерии фиксируются до теста на development benchmark. Нет автоматического «зелёного» статуса только из-за близости скважины или малой нейросетевой дисперсии.

Если posterior не сходится, missing completion/PVT определяет результат или реалистичные модели дают противоположные зоны, публикуются диапазоны/семейства либо отказ от локальной количественной оценки. Можно укрупнить support по заранее зарегистрированному правилу, но нельзя спрятать точность на произвольном масштабе после test.

## 15.3. Экспорт

Расчётные массивы и частицы — HDF5; табличные сводки — Parquet/CSV; GIS-растр — GeoTIFF только при подтверждённой CRS. Без неё сохраняется local-grid продукт с явным отсутствием геодезической аттестации. Цветовая карта не содержит фиктивного EPSG и не выдаётся за готовую координату бурения.

Каждый продукт содержит дату состояния, information mode, слой/support, единицы, priors/physics version, уровень наблюдаемости, posterior sample provenance и условные допущения. Median cube сопровождается хотя бы набором representative physical realizations. Файлы нельзя переименовать в «истинные остаточные запасы».

# 16. Инженерное применение: от So к решению

## 16.1. Выбор зон

Высокая So недостаточна: нефть может быть в малопроницаемой/недоступной зоне, иметь низкую kr_o, быть ниже экономического объёма или уже дренироваться соседней скважиной. Поэтому ранжирование начинается с оставшегося инвентаря, connectivity/uncertainty и ограничений размещения, затем проверяется физическим сценарием.

Сначала определяются допустимые зоны с поддержанным support; затем candidate geometry задаётся с учётом существующих стволов, охранных/технологических ограничений и неопределённости координат. При отсутствии этих сведений результат — исследовательская зона-кандидат, не утверждённая точка проектирования.

## 16.2. Парные контрфактические расчёты

Для каждой posterior-частицы выполняются два сценария с одинаковыми геологией/флюидами/неизвестностями: baseline без воздействия и scenario с новой скважиной/операцией. Политики существующего фонда и ограничения мощности/закачки фиксируются одинаково либо их различие явно относится к интервенции.

Новая скважина работает по физически допустимому BHP/ограничениям подъёма и жидкости, а не по заранее желаемому нефтяному дебиту. Основная выгода — **дополнительная нефть всего сектора** относительно baseline, а не собственная нефть новой скважины: часть её потока может быть перетоком отбора от соседей.

Выход: распределение incremental oil, воды/нагрузки, вероятность отрицательного или малозначимого эффекта, устойчивость ранга, зависимость от PVT/границ/подключений. NPV допускается лишь с отдельными подтверждёнными экономическими входами и их датами; не является обязательным доказательством локализации.

## 16.3. ГТМ и остаточная неподвижная нефть

В основном классе проверяются доразбуривание, изменение поддерживаемых подключений/изоляция воды и перераспределение закачки. ГРП можно моделировать только в согласованной зарегистрированной effective-WI/transmissibility постановке с неопределённостью, не объявляя её детальным моделированием трещины.

Химическое/тепловое изменение Sor, смачиваемости и фазовой физики требует собственной модели и данных. Нельзя взять зону So≈Sor, вручную уменьшить Sor и объявить найденные извлекаемые запасы. Карта такого объёма служит указанием на потенциальную задачу EOR-исследования, не доказательством эффективности ГТМ.

## 16.4. Ценность дополнительных измерений

При неопределённости формируется ranked measurement plan: датированное давление, PLT/профиль притока, повторная насыщенность в обсаженном стволе подходящим методом, трассер, уточнение подключений/траектории. Приоритет задаётся ожидаемым уменьшением неопределённости **решения**, а не только одного параметра.

Расчёт VoI использует синтетические возможные измерения и posterior update; их шум/стоимость явно предположены. Запрос документа о поздней изоляции иногда ценнее дополнительной нейросети. Отсутствие измерений не маскируется confident interpolation.

# 17. Программная архитектура и контракты

## 17.1. Технологический контур

Python — ETL, геостатистическая генерация/параметризация, ML, SMC, оценка и экспорт. Julia/JutulDarcy — физика и adjoint. Основная связь — один долгоживущий Julia worker-процесс с явными case files/job manifests, а не неявное состояние интерактивного notebook. Пакеты/методы загружаются и прогреваются один раз на worker; каждый job имеет изолированную model state и отдельный result path. Запуск нового Julia и повторная компиляция для каждой частицы запрещены как основной режим. Детерминированная очистка/reset и restart worker при обнаруженной утечке памяти обязательны. Доступный Python interface JutulDarcy может исследоваться, но не меняет контрактов.

Форматы: **Parquet** для канонических таблиц и particle metadata; **HDF5** для сеток, массивов, состояний/restart exchanges; **JSON/YAML** для версионированных схем/конфигураций. Native restart сохраняется в штатном формате закреплённой Julia/Jutul версии, отдельно от переносимых HDF5 state summaries; формат обмена не должен терять скрытые переменные black-oil. HDF5 summary не объявляется полноценным restart без round-trip test. Отдельный HDF5 shard на world/particle исключает несколько конкурентных writers в один файл. Версии библиотек фиксируются после совместимого smoke test: Python lockfile и Julia Project/Manifest обязательны.

Не создаётся production dashboard до готовности scientific gates. Достаточны командный pipeline, машинные артефакты, отчёт и статические карты. Отдельная web-платформа не является научной частью проекта.

## 17.3. Контракт CaseBundle

CaseBundle содержит schema_version, case/world/sector IDs, information_mode, cutoff/time axis, grid/cell geometry, rock arrays и topology, wells/connections, controls/constraints, fluid/relperm definitions, initial_state specification, boundary model, observation definitions/masks, latent renderer version, units, seeds и hashes источников. В нём нет скрытого обращения к глобальному CSV или к будущим наблюдениям.

`ThetaRecord` содержит discrete state, continuous latents, prior density components, transform/basis versions. Нельзя хранить только random seed без воспроизводимого generator version. `ForwardResult` содержит times, состояния/доступные checkpoints, фазовые поверхностные объёмы, connection flux summaries, pressure diagnostics, component balances, solver metadata, статус и затраты.

`PosteriorBundle` содержит particles, weights, log densities, genealogy, model hashes, diagnostics, MC estimates, budget ledger и ссылки на физические состояния. Один CSV с «средним So» не удовлетворяет контракту.

## 17.4. Интерфейсы проекта

Следующие имена — **контракты будущего проекта**, не заявление о существующих функциях API JutulDarcy:

### 17.4.1. Сохранение foundation и версий

E00 уже задаёт `ArtifactRef`, `RunContext`, immutable run outputs, resolved config и хэши. E01 расширяет эти механизмы; дублирующий registry не создаётся. Отпечатки машины и времени отделяются от детерминированных публикуемых manifest, как в E00. Pickle не может быть единственным долговременным scientific artifact.

Три вида статуса различаются: process/run (`RUNNING/PASS/FAIL` существующего E00), algorithm (`COMPLETE/INCOMPLETE_BUDGET/POSTERIOR_NOT_CONVERGED/NO_TARGET_SUPPORT`) и scientific outcome/gate. E01–E02 фиксируют их связь в схемах; успешная запись checkpoint не превращает незавершённый алгоритм в scientific PASS. Планы, конфиги и артефакты новой реализации используют spec_version=4.0; исторические E00 records сохраняют 3.0. До расширения runtime в E01 новый конфиг с 4.0 не поддержан текущей Literal-схемой — это известная задача перехода, а не причина пересоздавать проект.

# 18. Ресурсы: MacBook Pro M4 Pro 24 ГБ → более крупные расчёты

## 18.1. Базовый режим

Профили и их численные ограничения находятся в COMPUTE_PROFILES.md. По умолчанию: native ARM64 Python и Julia; JutulDarcy на CPU Float64; один Julia worker; ограниченная внутренняя многопоточность; BLAS без вложенного распараллеливания; PyTorch CPU с проверяемой MPS-опцией. Поддержка Julia на Apple Silicon документирована [R30](SOURCES.md#r30); совместимость полного набора зависимостей доказывается smoke test, а не только наличием ARM-бинарника.

MPS-обучение и CPU-симуляция разделены по фазам. 24 ГБ — общий бюджет CPU/GPU/ОС, а не две независимые памяти. Официальный GPU backend JutulDarcy описан как CUDA; ускорение через Apple GPU не закладывается [R28](SOURCES.md#r28). Переход к аренде сохраняет Python/Julia contracts, corpus shards и seeds; CUDA/много workers включаются после нового benchmark, не меняя научную постановку.

## 18.2. Измерение перед расширением

Для каждой новой сложности измеряются отдельно cold compile, warm-up, p50/p90 полного forward, память, failed/retry rate, restart I/O, обучение одной эпохи/пакета и стоимость complete SMC. Representative samples включают трудные prior families. Первый benchmark ориентировочно использует 5 warm runs, расширяется до 10–20 по нестабильности; p90 пяти запусков — разведочная оценка, не надёжный хвост распределения.

Составляется BudgetReport на **весь следующий эксперимент**: training, development, test truths, baseline inference, learned inference, repetitions, adjoints и output. Его стоимость не равна числу training worlds. Таблица только времени одного forward недостаточна.

## 18.3. Память и сохранение состояния

В RAM одновременно находятся один активный solver/adjoint, ограниченный minibatch/контекст и компактная particle table. Матрицы Jacobian и полные solver objects не хранятся для каждой SMC-частицы. Likelihood и нужные restart/state summaries кэшируются на диске; новая частица обрабатывается текущим worker.

Пользовательский бюджет проекта имеет soft/hard предел, проверку memory pressure, доступной памяти и swap growth. При превышении завершается текущая безопасная единица работы, сохраняется checkpoint, новые jobs не запускаются. Снятие MPS allocation guard не является допустимым решением OOM [R29](SOURCES.md#r29). Предел MPS задаёт GPU allocator, не RAM всего проекта; он не заменяет системный мониторинг.

`extra_outputs=false` в documented high-level API минимизирует набор state fields, но сам по себе **не доказывает streaming или O(1) память по времени** [R32](SOURCES.md#r32). Реальное поведение сохранения state/report_steps проверяется. Для обычного forward допускаются последовательные time-chunks с штатным restart, точными monthly integrals и reset-independent equivalence test. Для adjoint нужен собственный подтверждённый checkpoint/recompute режим; нельзя потерять path, затем заявить полный градиент.

## 18.4. Возобновляемость и длительный запуск

Long-run — это конфигурируемый **лимит сессии**, а не обещанный срок получения исследования. Профиль допускает явно выбранный запуск `wall_budget_hours=24` после успешного малого опыта и budget review. Истечение лимита даёт resumable/incomplete status. Финальная beta=1, convergence, calibration и scientific gates не обходятся из-за лимита.

Сохраняются номера завершённых jobs, SHA/config/version, RNG states, checkpoint сети/optimizer, beta/particles/weights/ancestry SMC, costs и pending work. Корпус детерминированно дополняется новыми parent IDs; старые splits не пересоздаются. Long-run не запускается агентом автоматически после E00/E01; требуется явный run intent пользователя и пройденные gates.

Неудачные симуляции учитываются. Resource failure и numerical failure не дают физический нулевой likelihood без анализа. Нельзя обучить сеть только на удобно сошедшихся мирах и скрыть selection bias. Повтор на другом hardware проверяется по numerical/MC tolerance, не обещает побитовую идентичность.

# 19. Gates, риски и допустимые исходы

## 19.1. Обязательные gates

| Gate | Что должно быть доказано | При провале |
|---|---|---|
| G_LOCAL | Малый полный цикл прошёл numerical/state/ambiguity diagnostics; стоимость известна | Разделить проблему кода, информации, ML и ресурсов; не запускать дорогой corpus |
| G_DATA | Единицы/идентичности/геометрия и пригодный пилот; существенные неизвестности представлены | Исправить данные/выбрать иной сектор; не начинать expensive inference |
| G_PHYS | Верифицирован выбранный физический класс, wells/events, баланс/restart; поле имеет PhysicsDecision | Исправить физику; исследовать сценарии, не маскировать ML |
| G_OBS | На development truth хотя бы инженерные зоны имеют полезную наблюдаемость | Укрупнить support по правилу или получать данные; не обещать локальную So |
| G_DENSITY | q/p0/L согласованы; toy SMC воспроизводит reference; residual retained | Исправить вероятностную реализацию до поля |
| G_ML | На закрытых мирах подтверждён вклад ML по state/calibration и полному бюджету | Отрицательный ML-вывод или только efficiency result |
| G_FIELD | Допустимы OOD/residual/backtests и sensitivity реального объекта | Сценарные/агрегированные продукты, не точная локализация |
| G_DECISION | Paired сценарии физически выполнимы и устойчивы | Зоны для доизучения вместо рекомендации бурить |

## 19.2. Главные риски

Неподтверждённые units/PVT могут искажать инвентарь; газ без давления — oil-specific So; отсутствующие события — ложный water-breakthrough; неизвестные границы — неверный баланс сектора; гибкие WI/noise — компенсация геологии; обрезанный residual — ложная уверенность; inverse crime — мнимая state accuracy; sparse particle modes — несходимость; expensive corpus — отсутствие cold-start выгоды; выбор геологии после будущих данных — утечка.

Для каждого риска в run registry есть owner, diagnostic, mitigation и влияние на научное утверждение. Наличие длинного списка алгоритмов не снижает эти риски само по себе.

## 19.3. Допустимые научные исходы

**A.** So наблюдаема на выбранном support, ML улучшает finite-budget inference, поле проходит косвенный контроль → количественный conditional posterior и инженерные сценарии.

**B.** Физическая реконструкция полезна, но ML не выигрывает → baseline posterior и честный отрицательный/ограниченный ML-результат; архитектура не даёт права заявить улучшение.

**C.** Скважинный отклик предсказывается, но So существенно неоднозначна → карты ambiguity/приоритетов доизучения; prediction accuracy не переименовывается в state accuracy.

**D.** Ни выбранный support, ни текущие внешние сведения не дают устойчивого состояния → обоснованная программа дополнительных данных и границы разрешимости. Это содержательный результат исследования, но не выполненное обещание точной карты остаточных запасов.

# 22. Первый сквозной опыт: что именно должно стать ясно на ноутбуке

## 22.1. Один короткий путь через настоящие компоненты

`P1_LOOP`: conditional prior → Jutul forward → noisy observations и скрытая truth → маленький graph-temporal NSF → defensive SMC → physical So ensemble → error/coverage/cost report. Используются те же контракты, masks, density rules и агрегатор, что будут у сектора. Это не одноразовый другой алгоритм и не постоянный mock simulator. Аналитический игрушечный posterior допустим для тестирования математики, но не считается физическим сквозным опытом.

## 22.2. Минимально содержательный учебный мир

Два слоя, несколько добывающих/нагнетательных скважин и совместное подключение хотя бы одной добывающей. K неоднородна, часть геологических данных неизвестна, режим закачки меняется. Неизвестны небольшой непрерывный транспортный блок, часть ОФП/So0 и хотя бы одна ограниченная дискретная гипотеза подключения или барьера. Распределения учебных PVT и их численные значения заданы отдельно как synthetic fixture; они не подписаны названием реального горизонта.

Матрица случаев:

| Случай | Проверяемый вопрос |
|---|---|
| T1 — информативное водное вытеснение | История уменьшает ошибку So относительно статического prior? |
| T2 — слои с похожим суммарным watercut | Сохраняется ли неопределённость распределения нефти по слоям? |
| T3 — канал/барьер и позднее подключение | Модель различает физические объяснения или сохраняет несколько мод? |
| T4 — удалённая слабодренируемая зона | Не появляется ли уверенная выдуманная So вне информационного покрытия? |
| T5 — несовпадение генератора и inference | Сгущённая сетка/иная ОФП/ошибка события ухудшают качество и обнаруживаются? |

Все T1–T5 — ограниченные development families малого мира, не пять больших проектов. Сначала запускается T1, затем остальные добавляют по одному осложнению. Ни один вариант не создаётся ручным изменением конечной So в обход баланса.

## 22.3. Что сравнить сразу

Минимум: static prior; prior-start SMC; raw NSF; NSF+SMC. Summary-NSF/temporal-set ablation добавляется в E03 в минимальном масштабе. MAP/ES-MDA и adjoint остаются обязательными сравнительными research-компонентами, но не являются зависимостью первого результата E03. Сравнение использует одни и те же truth worlds и полный ledger расходов.

В первом отчёте должны быть: true So и одна physical posterior realization; posterior median/width; RMSE на одинаковых report zones; prior error; фазовая history fit; ambiguity examples; status beta/convergence; таблица времени и памяти. Графики создаются кодом из данных, не генератором иллюстраций. Архитектурный комплект сам этих результатов не содержит.

## 22.4. Правило решения о продолжении

`PASS_CODE`: реальная физика, likelihood, q и SMC технически связаны; analytic density tests, monthly balance, restart и beta=1 выполнены.

`PROMISING_STATE`: на T1 есть воспроизводимое уменьшение state error; T2/T4 не дают ложной уверенности; направления ухудшения на T5 объяснимы. Численная цель раннего T1 — снижение RMSE относительно static prior хотя бы на 10% как **exploratory ориентир**, с отчётом всех worlds и variability. На столь малой выборке это не подтверждение статьи.

`PROMISING_ML`: ML+correction уже даёт лучший accuracy–cost tradeoff против prior-start SMC либо есть последовательное улучшение по увеличению корпуса. Нужны также runtime/cold-start расчёты. Один удачный seed недостаточен для сильного вывода.

Если `PASS_CODE` нет — исправить реализацию. Если state не различим даже контрольным inference — пересмотреть эксперимент/prior/support/доступные наблюдения, а не число GPU. Если state различим, но ML проигрывает — диагностировать encoder, coverage q, simulation distribution и training; ограниченный дополнительный малый раунд разрешён. Если всё перспективно, но дорого — разрешить увеличение сессии/аренду по BudgetReport. **Провал на несложном информативном мире не разрешает переход к дорогому сектору как способу исправления.**

После этого следует E07 на полеподобной геометрии/режимах. Успех на 512 клетках не доказывает успех на поле; он сокращает риск потратить ресурс на неверно собранную систему.

## 23.1. Численные критерии

На smooth verification cases начальные допуски: cumulative component-balance relative error ≤1e−3 и median per-step ≤1e−5; целевой более строгий контроль — §8.3. Normalization scale и absolute floor определяются до benchmark. Закрытое соединение имеет нулевой поток в численном допуске; отключение поверхности тестируется отдельно от закрытия соединений. Разница continuous/restart и grid/time refinement фиксируется по states, monthly integrals и inventory, а не только final scalar.

Для representative smooth parameters требуется `abs(g_adjoint−g_FD)/max(1,abs(g_adjoint),abs(g_FD)) < 1e−4` после объявления координат/масштаба параметров и шага FD. Проверяются также directional derivatives; совпадение только знака недостаточно. У discontinuities фиксируются односторонние проверки/статус невалидного градиента, применяется корректный gradient-free inference без подмены likelihood.

## 23.2. Воспроизводимость и статус результата

Каждый этап имеет `reports/stages/E##.md`: spec/stages/config version, commit и dirty state, входные hashes, команды/exit status, артефакты, измеренные метрики/ресурсы, ограничения и разрешённые зависимости. Исторический E00 сохраняется. Результаты новой схемы не объявляются уже реализованными из-за наличия текстового контракта.

Технические статусы этапа: NOT_RUN, IN_PROGRESS, PASS, PASS_WITH_LIMITATIONS, FAIL. Для E11 выполнение протокола может дать технический PASS и отрицательный scientific outcome. Research outcomes и каждый C_* gate записываются отдельно как SUPPORTED/NOT_SUPPORTED/INCONCLUSIVE с основаниями. Закрытые manifests и результаты неизменяемы; debugging после открытия инвалидирует набор для нового confirmatory claim. Тесты toy posterior и полный pipeline нужны оба; ни один не заменяет полевой контроль.

Финальный воспроизводимый synthetic путь: небольшой fixture с разрешёнными статическими наблюдениями → их канонизация → Jutul forward → inverse posterior → карты → проверка lineage/метрик. Реальные private CSV для него не требуются. Full field runs, ML обучение и long-run не запускаются как побочный эффект обновления документации.
